# LUCY Data Model

The first migration implements only foundation entities. Future objects are documented here so naming remains consistent.

## Foundation

- `users` — identity table, owned by Better Auth (migration `0002_auth.sql`)
- `sessions`, `accounts`, `verifications` — Better Auth (migration `0002_auth.sql`)
- `user_settings`
- `workspaces`
- `periods`
- `modules`
- `notes`
- `note_versions`

Better Auth tables keep that library's column names (camelCase mapped to
snake_case in `src/lib/auth/auth.ts`); booleans are `0/1` INTEGER and dates are
ISO-8601 TEXT, matching the rest of the schema.

## Added in Phase 2 (`0003_notes_rich.sql`)

- `folders` — optional bucket inside a workspace; `notes.folder_id` references it
- `tags` / `note_tags` — workspace-scoped labels, many-to-many with notes
- Note content is now Markdown (`content_json` = `{"type":"markdown","text":…}`);
  `notes.colour` and `notes.is_pinned` (from 0001) are now surfaced by the app

## General rules

- IDs are text UUIDs generated by trusted application code.
- Timestamps are UTC ISO-8601 text.
- Important user content supports soft deletion.
- Owner-scoped indexes are required.
- Database constraints complement application validation.
